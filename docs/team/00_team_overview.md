# RPG 프로젝트 팀 구성

## 프로젝트 개요
- **프로젝트명**: 던전 어드벤처 (Dungeon Adventure)
- **언어**: C++ (Visual Studio / MSVC)
- **유형**: 콘솔 텍스트 기반 턴제 RPG
- **목표**: 5~10분 플레이 가능한 미니 RPG

## 에이전트 간 협업 및 의사결정 규칙

### 1. 문제 발생 시 협의 원칙
- 개발 중 다른 에이전트의 모듈과 관련된 문제가 발생하면, **해당 에이전트와 직접 협의**하여 해결한다.
- 혼자 판단하지 말고, 관련 에이전트에게 문제 상황과 영향 범위를 공유한 뒤 함께 해결책을 도출한다.
- 예시: 전투 시스템(에이전트 2)에서 캐릭터 스탯 구조 변경이 필요하면, 캐릭터 시스템(에이전트 1)과 먼저 협의한다.

### 2. 의견 충돌 시 에스컬레이션
- 두 에이전트가 협의했으나 **의견이 합의되지 않을 경우**, 반드시 **설계자(메인 에이전트)**에게 보고한다.
- 설계자가 양측의 의견을 검토하고 **최종 결정**을 내린다.
- 설계자의 결정에는 모든 에이전트가 따른다.

### 3. 협의 절차
```
문제 발견
  → 1단계: 관련 에이전트와 직접 협의 (당사자 간 해결 시도)
  → 2단계: 합의 실패 시 설계자(메인)에게 에스컬레이션
  → 3단계: 설계자가 최종 결정 → 모든 에이전트 결정 따름
```

### 4. 협의 대상 매트릭스
| 상황 | 협의 대상 |
|------|----------|
| 캐릭터 스탯 변경이 전투에 영향 | 에이전트 1 ↔ 에이전트 2 |
| 전투 결과가 던전 흐름에 영향 | 에이전트 2 ↔ 에이전트 3 |
| 캐릭터 인벤토리가 상점에 영향 | 에이전트 1 ↔ 에이전트 3 |
| QA에서 발견된 버그 수정 방향 | 에이전트 4 ↔ 담당 에이전트 |
| 보안 이슈로 인한 구조 변경 | 에이전트 5 ↔ 담당 에이전트 |
| 다수 모듈에 걸친 변경 필요 | 설계자(메인)가 직접 조율 |

## 작업 흐름
1. **설계 단계** — 메인 설계자가 전체 구조, 인터페이스, 공통 헤더 정의
2. **병렬 개발** — 에이전트 1, 2, 3이 각 모듈을 동시에 개발
3. **통합** — 메인 설계자가 모듈 통합 및 빌드
4. **QA 점검** — 에이전트 4가 기능 테스트 및 버그 탐지
5. **보안 점검** — 에이전트 5가 보안 취약점 검사
6. **수정 & 완성** — 발견된 이슈 수정 후 최종 릴리스
