# 에이전트 3: 던전 & 게임 루프

## 역할
던전 탐험 시스템과 전체 게임 흐름을 개발한다.

## 책임 범위
- 던전 층 구조 및 이벤트 시스템
- 게임 메인 루프 (탐험 → 전투 → 보상 → 반복)
- 상점 시스템
- 휴식 / 회복 시스템
- 게임 시작 화면 및 엔딩 처리
- 텍스트 UI 유틸리티 (화면 정리, 구분선, 색상 등)

## 산출물
| 파일 | 설명 |
|------|------|
| `Dungeon.h` | 던전 클래스 선언 |
| `Dungeon.cpp` | 던전 클래스 구현 |
| `Game.h` | 게임 루프 선언 |
| `Game.cpp` | 게임 루프 구현 |
| `UI.h` | 텍스트 UI 유틸리티 선언 |
| `UI.cpp` | 텍스트 UI 유틸리티 구현 |

## 던전 구조
- 총 5층으로 구성
- 각 층에 3~5개의 방(이벤트)이 존재
- 마지막 층에 보스 등장

## 이벤트 유형
| 이벤트 | 설명 | 확률 |
|--------|------|------|
| 몬스터 조우 | 전투 시작 | 40% |
| 보물 상자 | 랜덤 아이템 획득 | 20% |
| 함정 | HP 감소 | 15% |
| 휴식처 | HP/MP 일부 회복 | 15% |
| 상점 | 아이템 구매/판매 | 10% |

## 게임 흐름
```
타이틀 화면
  → 캐릭터 생성 (이름 입력, 직업 선택)
  → 던전 입장
    → 층 탐험 (방 이동)
      → 이벤트 발생 (전투/보물/함정/휴식/상점)
      → 다음 방 또는 다음 층으로 이동
    → 보스 처치 시 클리어
  → 엔딩 화면 (스탯 요약)
```

## 협업 규칙
- 다른 에이전트의 모듈에 영향을 주는 변경이 필요할 경우, **해당 에이전트와 먼저 협의**한다.
- 특히 전투 호출 방식 변경 시 전투 시스템(에이전트 2), 아이템/상점 관련 변경 시 캐릭터 시스템(에이전트 1)과 반드시 사전 협의한다.
- 협의 후에도 의견이 합의되지 않으면 **설계자(메인 에이전트)에게 보고**하고, 설계자의 최종 결정에 따른다.

## 인터페이스 요구사항
- `Game` 클래스가 `Character`, `Combat`, `Dungeon`을 조합하여 게임 진행
- `UI` 유틸리티는 모든 모듈에서 공통으로 사용
- 게임 오버 시 재시작 옵션 제공
